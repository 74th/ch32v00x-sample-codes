# spi_master（公式WCH SDK、CH32V003）

書籍`spi_master-wch_sdk`の移植。SPI1マスタ（PC5 SCK、PC6 MOSI、PC7 MISO、mode 0、MSB first、分周256＝187.5 kHz）でADT7310系の温度センサーを読む。
起動時: CS High 500 ms → リセットフレーム`FF FF FF FF`、100 ms、コマンド`0x54`、300 ms。ループ: 2バイト読み出し→13bit符号付き変換（`adt7310.c`）→`raw`/`raw_int`/`temp`をUSART1 TX（PD5）へ、1秒周期。
公式`SPI_Init`/`SPI_I2S_*`を使用。Flash 6,956 B／RAM 696 B。変換は書籍の式のまま`adt7310.c`に分離し、ホストでも単体テストする。

## 書籍との差（CS配線と観測のため）
- **CSはPC0**（書籍はPC1だが、治具のPC1はI2C SDA）。CSはリセット/設定フレームの終了後と、2バイト読み出しごとに戻す（書籍はCSを常にLowのまま）。
  PicoのSPI slaveは「CS1回あたり2バイト」を処理する仕様のためCS Low固定には追従できない。リセット＋設定は1回のCS Low期間内。
- 結果テキストは読み出しの300 ms後に出し、最後の待ちを700 msに短縮（周期は同じ1 s）。Picoは1コマンドずつなので、SPIフレーム処理後にテキストを捕捉する。
- **実センサーでCSを毎フレーム戻しても書籍と同じ読み出しになるかは未確認**（ADT7310の連続読み出しモードの挙動は未検証）。
- 書籍の変換は負値を`floor`＋小数部で表示するため、−25.5 ℃は`-26.5000`と表示される（書籍どおり、未修正）。

## 観測
- ホスト（`tests/unit/test_wch_adt7310.py`）: 手計算の既知値（`0c80`→25.0000、`0c88`→25.0625、`f380`→-25.0000、`ffff`、`7ff8`）と負値の書式。
- HIL（`uv run pytest --hil --hil-framework wch tests/hil/wch/test_spi_master.py`、実測）: PicoがSPI slave（mode 0）。
  リセットフレームの先頭2バイト`ffff`、その後CSが約400 msLow→High、読み出しフレーム`0000`（周期約1.0 s）、返答`f380`に対しDUTが`raw: f380 / raw_int: -400 / temp:-…`、`0c80`に対し`raw: 0c80 / raw_int: 400 / temp: 2…`を出力。
- 0x54以降のバイト（リセットフレームの3バイト目以降）はPicoが取らないため、CS Low期間の長さで間接的に確認しただけ。

## 既知の間欠現象
リセットフレームの先頭バイトでPicoが先頭ビットを0と読み、`7fff`になることが17回中2回あった（以降10回は発生せず）。DUT SPIのMOSI先頭ビットの確定がSCKに対して不安定な可能性があるが、波形は未観測で原因未確認。HILは`ffff`/`7fff`のみ許容し記録する。実センサーのリセット（FF×4）への影響は未評価。
