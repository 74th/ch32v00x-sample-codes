# Spec Delta

## MODIFIED Requirements

### Requirement: 固定ツールと対象識別

DUTのbuildとflashは `externals/ch32fun` の固定submoduleを使用し、検出出力と必要な識別領域を確認して、対象不明または誤識別の状態で成功としてはならない（SHALL NOT）。

#### Scenario: CH32V003へ書き込む
- **WHEN** CH32V003用成果物を書き込む
- **THEN** 固定minichlinkが対象型番と書き込み完了を確認し、選択したポリシーでreadback一致を確認できる

#### Scenario: CH32V002へ書き込む
- **WHEN** CH32V002用成果物を書き込む
- **THEN** 固定minichlinkの検出出力に加え、識別領域 `0x1ffff704` の型番部分が `0x002` であることを書き込み前に確認し、書き込み完了と選択したポリシーでのreadback一致を確認できる

#### Scenario: DUTを検出できない
- **WHEN** minichlinkが未接続、unknown chip、期待外型番、または曖昧な成功出力を返す
- **THEN** テストランナーはflash段階を失敗とし、観測段階へ進まない

#### Scenario: 識別領域が選択デバイスと一致しない
- **WHEN** 選択したデバイスと識別領域の型番が一致しない、または識別領域を読めない
- **THEN** テストランナーは書き込み前に失敗し、DUTのflashを変更しない

## ADDED Requirements

### Requirement: HIL対象デバイスの明示選択

テストランナーは、HILの対象デバイスを利用者が明示選択でき、選択したデバイス用のサンプル、設定、期待型番だけを使って実行しなければならない（SHALL）。

#### Scenario: CH32V002を選択してHILを実行する
- **WHEN** 利用者がCH32V002を対象デバイスとしてHILを実行する
- **THEN** CH32V002用のサンプルと設定が使われ、開始時に対象デバイスと破壊的影響が表示され、結果に対象デバイスが記録される

#### Scenario: デバイスを指定しない
- **WHEN** 利用者が対象デバイスを指定せずにHILを実行する
- **THEN** 従来どおりCH32V003を対象とし、既存のCH32V003用コマンドの結果は変わらない

#### Scenario: 選択デバイスに未対応のテスト
- **WHEN** 選択したデバイス向けのサンプルまたは設定が存在しない、またはマトリクスで対象外とされている
- **THEN** そのテストは理由付きでskipされ、成功として報告されない

#### Scenario: 不明なデバイスを指定する
- **WHEN** 利用者が対応していないデバイス名を指定する
- **THEN** テストランナーは実機操作の前に設定エラーとして停止する
