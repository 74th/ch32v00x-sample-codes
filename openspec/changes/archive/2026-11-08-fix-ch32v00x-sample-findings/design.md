# Design

## Context

対象の一覧と動機は `proposal.md` を参照。指摘の出所は、書籍原稿の執筆時のレビュー（`okf/log/2026-11-08-2019-ch32v00x-book-articles.md`）です。
各項目は、コードを読んだうえでの指摘で、実機ではまだ確かめていません。

計画の時点で、次の点はソースで確認済みです（e8f76c4、`samples_ch32v002_wch` 側。006も同じソース）。

- `timer_dma/main.c:132-136`: PSC=480、Period=10−1、コメントは「10usごとにトリガ」。直前に `4800 - 1` の設定で `TIM_TimeBaseInit` を1回呼んでいる。
- `sleep_wake/main.c:42-43`: コメントは「50…1Hz」、値は `20 - 1`。
- `standby_wake/main.c:60-63`: コメントは「window value 31」、値は25。
- `timer_blink/main.c:70`: コメントは「IPRIOR[8]」。SDKの `core_riscv.h:91` は `IPRIOR[256]`。
- `i2c_slave/main.c:125-130`: `I2C_ClockSpeed` を設定していない（`{0}` で初期化）。
- `samples_ch32v002_arduino/i2c_slave/i2c_slave.ino:20,35-36`: `position + (i - 1)` で判定し、`position + i` を読んでいる。
- 固定ch32funの `ch32fun.c:2260-2296` の `funAnalogInit()` は、CH32V20x以外では `EXTTRIG` を立てず、`RSTCAL`/`CAL` が下がるのを待つ。

## Goals / Non-Goals

**Goals:**
- サンプルの説明と値を一致させる。
- 選べるのにbuildできない分岐と、未初期化の設定をなくす。
- 範囲外アクセスをなくす。
- 原因未特定の事項を、実機の根拠のある記録に進める（原因を特定できなくても、試した条件と結果を残す）。

**Non-Goals:**
- `externals/ch32fun` の変更。
- CH32V003版サンプルの修正。同じ箇所があることを記録するだけにする。
- 書籍原稿の更新。
- 電圧・電流・時間精度の校正測定。測定器の追加が要るため、必要性を記録するだけにする。

## Decisions

### 1. 修正は「コメントのみ」と「動作の変更」に分ける

コメントや文字列だけを直す修正は、buildした成果物（`.bin`）が変わらないことを、修正前後のハッシュ比較で確かめます。
これにより、既存のHIL結果を引き継げます。
動作が変わる修正（`i2c_slave` のクロック、Arduinoの範囲判定、`i2c_master` のリマップ分岐）は、002と006の両方でbuild・flash・HILをやり直し、マトリクスとログを更新します。

### 2. リマップ分岐は資料で確定できなければ止める

002/006用SDKには、`GPIO_PartialRemap1..3_I2C1` と `GPIO_FullRemap4_I2C1` があります。
どの定数がどのピンに対応するかを、リファレンスマニュアルのAFIOの表で確かめます。
固定治具はPC1/PC2に配線しているため、リマップ側は実機で観測できません。
資料で確定できた場合も「buildのみ」として扱い、確定できない場合は `#error` で未対応を明示します。

### 3. I2CスレーブのClockSpeedは、masterと同じ100 kHz（標準モード）を設定する

スレーブのSCLはmasterが駆動しますが、SDKの `I2C_Init()` はClockSpeedからCKCFGRを計算します。
0のままでは除算の経路に入るため、`100000` を設定します。
設定後のCKCFGRの値は、診断用のビルドかデバッガで読み、ログに残します。

### 4. Arduinoの範囲判定は、書き込みと読み出しで同じ添字を使う

受信と送信のどちらも、実際にアクセスする添字で範囲を判定するように直します。
範囲外は、読み出しなら0xFFを返し、書き込みなら捨てます。
Wire slaveの固着（既知の問題）とは別の問題として扱い、固着が解決したとは主張しません。

### 5. 調査は、実機が要るかどうかと、DUTの差し替えが要るかどうかで並べる

ソースや資料の照合だけで済むもの（ADC_CLK_MODE、DMA割当、zmmul、PinMap_TIM、SPIの分周）を先に行います。
次に、現在のDUTのまま実機でできるもの（funAnalogInit、standbyの文字化け、SWIO printf、Arduinoのprintf、SPIクロック、WS2812）を行います。
最後に、DUTの差し替えや追加の部品が要るもの（PC4の別個体、IWDGのLSI）を行います。
各調査は `okf/log/` に1件ずつ記録し、結論が出たものは `okf/` の知識として整理します。

### 6. 新しい事実は既存のマトリクスと知識に反映する

マトリクスの状態は、実機の再試験の結果でのみ変えます。
調査で結論が出た事項は、`okf/peripherals/` の差分文書の該当節を更新します。
CH32V003版にも同じ不整合がある場合は、ログに記録だけします。

### 7. 未確認事項は1か所の一覧で管理する

書籍原稿の「確認していない」事項を、`okf/` の知識として1つの一覧（`okf/open-questions/ch32v00x-unverified.md`、type: Open Question）にまとめます。
各項目には次を書きます。

- 対象デバイス
- 分類: 今の治具で確認／治具の追加／測定器・実物・別個体／GUI操作／サンプルなし／資料
- 状態: 未着手／確認済み／保留
- 根拠となるログ

この change では「今の治具で確認」と「資料」の項目を行い、それ以外は必要なものを書いて保留にします。
保留の項目を進めるかは、ユーザーが機材や個体を用意してから、別のchangeで決めます。

乗算命令は、逆アセンブルで命令が生成されていることを確かめたうえで、既知の積（符号付き・符号なし、上位ワードを含む）を計算してUARTに出力する試験ファームウェアを002/006で実行し、ホストで期待値と比べます。
試験ファームウェアはサンプルとして維持せず、診断用としてログに手順とソースの所在を残します。

## Risks / Trade-offs

- [コメントの修正のつもりで、意図しないコードの変更が入る] → 修正前後の成果物のハッシュを比較する。
- [PC4やIWDGは、別個体がないと切り分けられない] → 手元の個体で試せる範囲を記録し、別個体が要るものはユーザーに確認したうえで保留にできるようにする。
- [funAnalogInitが停止するとDUTが応答しなくなる] → タイムアウト付きの診断ビルドで確かめ、復旧手順（blinkの書き込みと読み戻し）を後片付けに含める。
- [Arduinoの範囲判定の変更で、書籍のコードとの差が増える] → 差分をサンプルのREADMEに記載する。
