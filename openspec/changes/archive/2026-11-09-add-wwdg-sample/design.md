# Design

## Context

動機と範囲は `proposal.md` を参照。ソースと資料で確認済みの事実（CH32V00X RM V1.5 第5章、`ch32v00X.h`、公式 EVT `EXAM/WWDG`）は次のとおり。

- 7 ビットのカウンタが HCLK/4096 を WDGTB で 1/2/4/8 に分周したクロックで減る。有効化（WDGA=1）後は、リセットが起きるまで止められない。
- リセット条件は2つ。カウンタが 0x40 から 0x3F になる（T6 が 0 になる）ことと、カウンタが窓の値 W 以上のときにフィード（T への書き込み）をすることの2つ。
- 早期割り込み（EWI）は、カウンタが 0x40 になったときに出る。
- 公式 EVT の例は、`WWDG_Config(0x7f, 0x5f, WWDG_Prescaler_8)`（コメントは「48M/8/4096」）で、10 ms ごとに現在のカウンタが窓の値を下回っていればフィードする。EWI の割り込みも有効にしている。
- 維持している 002/006 の SDK のコピーには `ch32v00X_wwdg.{c,h}` がない（IWDG は `ch32v00X_iwdg.{c,h}` として入っている）。固定 ch32fun のヘッダには `WWDG_TypeDef`（CTLR、CFGR、STATR）がある。
- 書籍の WCH SDK の対応表と単体テストは、WCH の `matrix_ch32v00{2,6}_wch.json` が書籍の13例と1対1で、行数も13であることを前提にしている（`tests/unit/test_config_matrix.py`）。ch32fun のマトリクスには、書籍由来でない行（`book_sample` が null）がすでにある。

## Goals / Non-Goals

**Goals:**
- WWDG の3つの動作（窓の内側、窓より早い、フィードしない）を、002 と 006 の実機で区別して観測できるサンプルとHILにする。
- 書籍にないサンプルを、書籍の13例の対応表を壊さずに追跡する。

**Non-Goals:**
- EWI の動作、デバッグ中の動作、リセットまでの時間の絶対精度の確認。
- 消費電流、電圧、温度の影響。
- Arduino 版、CH32V003 版。

## Decisions

### 1. 動作の切り替えは、ビルド時の定義で行う

`-DWWDG_MODE=<n>`（0 = 窓の内側でフィード、1 = 窓より早くフィード、2 = フィードしない）で3つの動作を切り替える。HIL は、`Dut.make_args` で3つのビルドを順に書き込む（`ssd1306` の `HELPER_CLOCK` と同じ流儀）。
代替案の「Picoが PA1/PA2 を駆動して実行時に切り替える」は、入力の RC（10 kΩ＋1 µF）の時定数（約10 ms〜50 ms）が WWDG の窓（数十 ms）と同じ桁で、切り替えの遅れが結果に混ざるため採らない。

### 2. 窓とクロックは、ms 単位で区別できる値にする

HCLK 48 MHz、WDGTB=3（/8）で、1 カウントが約 683 µs。RM の式（T[5:0]+1 カウント）では、0x7F からの時間切れが約 43.7 ms（64 カウント）。窓の値を 0x5F にすると、窓が開くのは約 22.5 ms（33 カウント）後。
公式 EVT の例と同じ値なので、書籍にない内容でも出典を示せる。Pico の時計が未校正で、観測の分解能が粗くても、10 ms 対 43 ms は区別できる。

### 3. フィードは、公式の例と同じく「カウンタが窓の値を下回ったら」で行う

「窓の内側」のビルドは、5 ms ごとのループで、現在のカウンタ（`WWDG->CTLR` の T[6:0]）が窓の値を下回っているときだけフィードする。`Delay_Ms` の精度に頼らず、窓の内側に入ることを保証できる。
「窓より早い」のビルドは、条件なしに毎ループ（5 ms）でフィードする（カウンタが約 0x77 のときに書くのでリセットされるはず）。「フィードしない」のビルドは、有効化した後に書かない。

### 4. 観測は、リセット要因のテキストと、起動後の点の数で行う

起動時に `RCC_RSTSCKR` の `WWDGRSTF`（bit 30）と `IWDGRSTF`（bit 29）を読み、フラグを消して、UART（PD5、115200）に `cause=WWDG`、`cause=IWDG` または `cause=other`（改行は `\n` のみ）を出す。有効化の後は、ループで `.` を1文字出してから 5 ms 待つ（点を先に出す。フィードでリセットされるとき、送信中の点が切れないようにするため）。
- 窓の内側: 点が増え続け、起動メッセージが繰り返されない（リセットされない）。
- 窓より早い: 点が1個でリセット（cause=WWDG）。
- フィードしない: 点が9個（0、5、…、40 ms）でリセット（cause=WWDG）。
点の数は、フィードのタイミングの違いの粗い目安であり、時間の精度の測定ではない。UART は 1 回に最大 32 バイトしか取れないので、出力はその範囲に収まる短いものにする。起動テキストは 12 バイト（`cause=other\n`）で、`wait` の行は出さない（実機の最初の実装では `wait\r\n` を出したが、起動2回分が 32 バイトに入らなかったため削った。モード 2 は `cause=other\n` + 点9個 + `cause=WWDG\n` でちょうど 32 バイト）。

### 5. 有効化の前に待ちを入れる

WWDG は有効化の後に止められず、リセットを繰り返すと、書き込み器（minichlink）が接続できず、書き換えや復旧ができなくなるおそれがある。起動直後に 1〜2 秒の待ち（UART には何も出さない）を入れてから有効化する。待ちの長さは 1.5 s に決めた（実機の診断では、WWDG が有効なままリセットを繰り返すビルドでも、検出・書き込み・読み戻しができた。ログ参照）。
HIL は、各試験の最後に既知のサンプル（`blink` など）を書き込み、検出と読み戻しで復旧を確認する（`standby_wake` の復旧と同じ）。

### 6. WCH SDK へのドライバの追加は、コピーと出所の記録で行う

`ch32v00X_wwdg.{c,h}` を公式 EVT（`externals/ch32v002_004_005_006_007/EVT/EXAM/SRC/Peripheral/`）から、002 と 006 の `sdk/` にコピーする。`PROVENANCE.md` の表にコピー元とハッシュを追記し、`ch32v00X_conf.h` にヘッダを加える。ビルドは維持している SDK だけを使う（externals には依存しない）。既存の成果物のハッシュは変わらないことを確かめる。

### 7. マトリクスは、書籍由来でない行を種別で区別する

新しい種別（`additional-not-in-book`）を `CLASSES` に加え、`book_sample` は null にする。WCH のマトリクスの単体テストは、「書籍の13例が1対1」と「追加の行は種別が `additional-not-in-book`」に分けて判定するように直す。ch32fun のマトリクスにも同じ種別で行を追加する。
代替案の「`equivalent-standard-ch32fun` で追加する」は、書籍と同等であることを意味する種別なので、書籍にない内容には不正確で採らない。

### 8. ch32fun 版は、レジスタを直接操作する

固定 ch32fun のヘッダの `WWDG`（`WWDG->CTLR`、`CFGR`）と `RCC->APB1PCENR` の `RCC_WWDGEN` を使う。WCH SDK 版と同じ窓・分周・動作の切り替え（`-DWWDG_MODE`）で、002/006 共通のソースにする。固定 ch32fun は変更しない。

## Risks / Trade-offs

- [WWDG を有効にした状態では、書き込み器が接続できなくなるおそれ] → 有効化の前に待ちを入れ、各試験の後に既知のサンプルで復旧と読み戻しを確認する。復旧できない場合は、電源の入れ直し（WCH-LinkE の 3.3 V）で行う。
- [HSI の精度が未校正で、窓の境界が実際の時間とずれる] → 窓の内側と外側を、境界から十分に離れた値（5 ms ごとのフィードと、10 ms 対 43 ms の違い）で判定し、境界の精度は主張しない。
- [Pico が1回に取れるのは 32 バイトまで] → 出力を短くし、点の数は目安として扱う。
- [RM の記述に不整合がある（窓の下限を 0x3F とする図と、0x40 を下回ると本文）] → 実機の結果を優先して記録し、資料との差が出たら記録する。
- [WCH のマトリクスの単体テストの前提を変える] → 書籍の13例の1対1の判定は残し、追加行の判定を足す形にして、既存の確認を弱めない。

## Open Questions

- EWI（早期割り込み）を使うサンプルを足すか。今回は未確認として残す。
- 有効化の前の待ちの長さ: 1.5 s とした（実機の診断で、この待ちがあればデバッガが接続できた。待ちを短くした場合の影響は調べていない）。
