# Proposal

## Why

CH32V002へ移植する前に、既存のCH32V003とch32funの組み合わせを再現可能な基準環境として確立し、ツール、書き込み方法、実機確認方法を切り分ける必要がある。既知の構成で基準を作ってからCH32V002へ進むことで、環境起因の問題とデバイス差分による問題を区別できるようにする。

## What Changes

- `externals/ch32v003-book-code`の既存ch32funサンプルを、記録されたツールと手順でビルド、書き込み、CH32V003実機上で確認できる基準ワークフローを作る。
- 最初の基準サンプルをGPIOの既知パターンに絞り、ビルド成功、書き込み成功、実機動作をそれぞれ区別して記録する。
- Raspberry Pi Picoを使った最小のGPIO観測スタブを用意し、DUTの出力を機械的に取得できる観測経路を確立する。
- 基準ワークフローをCH32V002F4P6向けへ移植し、CH32V003から必要になった変更をデバイス差分として記録する。
- CH32V002版もビルド、書き込み、実機動作まで確認し、未確認の状態を成功として扱わない。
- 使用した外部リポジトリのコミット、ツールバージョン、対象型番、配線、実行コマンド、観測結果を再現可能な形で残す。
- CH32V003のデータシートとリファレンスマニュアルを非公開Markdown化し、CH32V003実機基準を確定する前に参照可能にする。この抽出作業はch32funビルド・書き込み環境の構築と並行してよい。PDFおよび全文変換物は`xprivate/`に留める。

## Capabilities

### New Capabilities

- `ch32fun-sample-workflow`: CH32V003で基準を確立してからCH32V002へ移植し、各段階のビルド、書き込み、実機動作と再現情報を検証するワークフロー。

### Modified Capabilities

なし。

## Impact

- CH32V003およびCH32V002向けのch32funサンプルとビルド設定
- ch32funサブモジュールまたは参照方法、RISC-Vツールチェーン、WCH-Link系書き込みツール
- 実行手順、対象デバイス設定、配線、検証結果を保持する文書または設定
- `externals/ch32v003-book-code`は参照元として扱い、原則として直接変更しない
- 完成版の自動HIL基盤、他のCH32V00x、全周辺機能の移植はこのchangeの対象外
