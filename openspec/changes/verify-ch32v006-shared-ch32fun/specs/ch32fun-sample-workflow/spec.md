# Spec Delta

## MODIFIED Requirements

### Requirement: CH32V002サンプルの配置と依存

維持するCH32V002/ch32funサンプルは、CH32V006との共通化条件が成立するまでは `samples_ch32v002_ch32fun/<sample>/` に置き、成立後は `samples_ch32v00x_ch32fun/<sample>/` に置かなければならない（SHALL）。build依存は固定 `externals/ch32fun` の標準機能および「固定submoduleのhelper検証」で許可されたhelperに限定する。

#### Scenario: CH32V002サンプルをビルドする
- **WHEN** CH32V002向けサンプルをビルドする
- **THEN** 固定submoduleの `ch32fun.mk` と標準ヘッダだけを使い、「固定submoduleのhelper検証」で許可されたhelper以外の `extralibs`、book-code内のch32fun、PATH上のツールに依存しない

#### Scenario: 共通化条件が成立する
- **WHEN** 共通化対象の全サンプルについてCH32V002/CH32V006で共通化条件が成立する
- **THEN** 維持するソースを `samples_ch32v00x_ch32fun/` に移し、現行の実行手順・設定・マトリクスを移行先に更新する
- **AND** 過去ログの旧パスは当時の証跡として保持する

#### Scenario: 共通化条件が未成立である
- **WHEN** ソース共通化の阻害差分または必須の実機未確認項目が残る
- **THEN** 配置変更を保留し、対象サンプル・理由・未確認事項を明示する

### Requirement: CH32V002サンプルのデバイス差分記録

CH32V002向けに移植した各サンプルは、CH32V003版からのターゲット指定、クロック、メモリ、ピン機能、AFIOリマップ、レジスタ、期待値の変更点と資料上の根拠を記録しなければならない（SHALL）。共通配置へ移した後も出典と差分の記録を保持しなければならない（SHALL）。

#### Scenario: 周辺機能サンプルを移植する
- **WHEN** `samples_ch32v003_ch32fun/<sample>/` を基にCH32V002向けサンプルを作成する
- **THEN** 変更点ごとにデータシートまたはリファレンスマニュアルの版とページ、あるいは実測ログへの参照が記録され、資料確認済み・実機確認済み・未確認が区別される

#### Scenario: 変更不要と判断する
- **WHEN** CH32V003版のコードをCH32V002向けに変更せずに使う
- **THEN** 変更不要と判断した根拠が記録され、無根拠な互換性の仮定として扱われない

## ADDED Requirements

### Requirement: CH32V006への段階的検証

ワークフローはCH32V006F8P6の型番、電源・SWIO・使用信号の物理ピン、クロック、メモリ、GPIO、使用周辺機能を一次資料と照合したうえで、GPIOのbuild・flash・readback・Pico観測を完了してから既存の周辺機能HILへ進まなければならない（SHALL）。

#### Scenario: CH32V006で最初のGPIO試験を行う
- **GIVEN** 対象部品・基板・配線・給電条件が記録されている
- **WHEN** CH32V006向けGPIO試験を実行する
- **THEN** build、対象識別付きflash、成果物全体のreadback一致、PicoによるPC0点滅観測を個別に記録する
- **AND** いずれかの段階が失敗した場合は周辺機能の検証完了としない

#### Scenario: 既存の周辺機能試験へ展開する
- **GIVEN** GPIOの最小ループがCH32V006実機で成功している
- **WHEN** UART、I2C master/slave、SPI master、timer/PWM、ADC、watchdog、sleep、指定helperを検証する
- **THEN** CH32V002の既存HILと同じ刺激・期待値・許容差を基準に判定し、変更が必要な項目は根拠と適用デバイスを記録する

### Requirement: CH32V006の独立した検証マトリクス

CH32V006のマトリクスはCH32V002マトリクスの全対象行に対応し、サンプル、配線、治具能力、合否条件、状態、対象型番に対応する実測証跡を独立して追跡しなければならない（SHALL）。ソース共有によって実機検証状態を共有してはならない（SHALL NOT）。

#### Scenario: CH32V006用マトリクスを初期化する
- **WHEN** CH32V002の項目を基にCH32V006マトリクスを作る
- **THEN** CH32V002の確認済み状態・実測証跡をCH32V006の確認済み状態へ転用しない
- **AND** gpio_inputの配線制約や未対応項目は理由付きで記録する

#### Scenario: CH32V006のサンプルを確認済みにする
- **WHEN** 対象サンプルの必須HILがCH32V006実機で成功する
- **THEN** build・flash・readback・観測の結果、型番、ソースrevision、ビルドターゲット、ツール、配線、実行コマンドを含むログを参照して確認済みにする
- **AND** skip、xfail、buildだけの成功を実機確認済みにしない

### Requirement: 共通ソースへの移行条件

CH32V002/CH32V006の共通配置への移行は、対象の全12サンプルでデバイス別のアプリケーション実装や分岐を追加せず、ターゲット・リンク・ビルド設定の選択だけで両デバイス向けにビルドでき、同一ソースrevisionで両実機の必須HILが成功した場合に限らなければならない（SHALL）。同じバイナリであることは条件にしない。

#### Scenario: 同じソースで両デバイスの検証が成立する
- **WHEN** 全12サンプルが両ターゲットでbuildでき、両実機の必須HILが成功する
- **THEN** 共通化可能と判断し、ターゲット別メモリ設定・成果物・実機証跡を保持したまま共通配置へ移行できる
- **AND** SSD1306 helperの1 MHz参考試験は必須成功条件から除外して独立結果を残す

#### Scenario: デバイス固有の処理が必要になる
- **WHEN** CH32V006の検証で周辺機能処理・タイミング処理などのデバイス別実装や分岐が必要と判明する
- **THEN** 共通化成立とせず、最小差分と観測結果を記録して配置変更を保留する

### Requirement: 共通配置の対応範囲とREADME

READMEは共通ソースの配置、デバイスを選んだビルド・HILコマンド、移行前後のパス、デバイス別検証結果へのリンク、未確認範囲を記載しなければならない（SHALL）。ディレクトリ名の `ch32v00x` をシリーズ全体の互換性・実機検証の保証として扱ってはならない（SHALL NOT）。

#### Scenario: 共通配置へ移行したREADMEを読む
- **WHEN** 共通化条件が成立してREADMEを更新する
- **THEN** CH32V002F4P6とCH32V006F8P6で同じアプリケーションソースを使いターゲット別にビルドすること、CH32V003は別配置であること、CH32V005/007と別パッケージは未検証であることが分かる

#### Scenario: 共通化を保留した結果を読む
- **WHEN** 共通化条件が成立しないまま検証結果をREADMEに記載する
- **THEN** 現在の配置と共通化保留の理由、CH32V006で確認できた範囲が明記され、未達の共通化を完了と表現しない

#### Scenario: 機能試験の結果を解釈する
- **WHEN** READMEに周辺機能またはhelperの成功を記載する
- **THEN** ADC精度、タイミング規格適合、消費電流、実OLED表示・実LED発光の未確認を機能試験の成功と区別する
