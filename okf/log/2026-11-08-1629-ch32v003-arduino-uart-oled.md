## 目的と方針
書籍の uart スケッチは CO2 値を OLED にだけ出す。Pico の呼び出しは排他的で、センサー応答（UART）と OLED 取り込みを同時にはできない。DUT の受信は割り込みでバッファに溜まるので、応答を先に送り込み、直後に取り込みを開始する順序で成立させる。

## 作ったもの
- `samples_ch32v003_arduino/uart_96x16/`（書籍からの逸脱: 96x16 宣言と状態行 y=20→0）。003 向け build 成功、Flash 14,028 B / 16,384 B、RAM 1,120 B。
- ホスト harness（`tests/unit/arduino_oled/uart_harness.cpp`、Serial の模擬を `Arduino.h` に追加）と `expected_uart_screens`: スケッチ自体と固定ライブラリで、ループごとの画面を描画する。
- HIL `tests/hil/arduino/test_uart.py::test_arduino_uart_co2_to_oled`（003 は 96x16 変種、006 は書籍のスケッチを使う）。

## 失敗と分かったこと（実測）
1. 初回実行（変種のY座標は 8/20 のまま）: 読み取りコマンドの捕捉・フレーム投入は成功。取り込みは `ERR TIMEOUT`、data=480 B。**96x16 では 2 行目（y=20）が範囲外で描かれない**ことが原因の一つで、座標を 16 行に収めた。
2. **INIT なしの取り込みでは、モデルは表示初期化を見ていないのでページアドレスモード**になる（各 display() が毎回ページ 0.. を上書き、フレームは完了しない）。INIT 付きでは連続（水平）モードで、フレーム数どおりに完了する（i2c_oled_96x16 の実測）。DUT のリセット後に INIT 付きで取り込むと、UART 応答を挟めない（排他的）ため今回は INIT なしを使う。
3. **最後の I2C 転送のデータは次の START まで確定しない**（モデルの挙動。`data`・ページ内容の時間変化と、表示ごとに最終ページだけが欠けることから推定）。取り込みを表示の直後に打ち切ると最終ページが空になる。判定は最終ページを除いたページで行う。
4. タイミング（実測、reset 後の経過）: loop 1 の読み取りコマンド 2.48 s、フレーム投入 3.83 s、取り込み開始 ~3.9 s。1.5 s の取り込みで loop 2 の表示（co2 画面）が入り、loop 3 の表示は ~2.8 s 後。
5. 診断: Pico は取り込み中に届いた別コマンド（UART_XFER）を待たせ、取り込み終了後に実行する（同時実行ではない）。

## 結果（実測）
- 003 の `test_arduino_uart_co2_to_oled`: 3 回連続で passed（各 約 11.6 s）。ページ 0（CO2 行）がホストで描画した「co2 : 1234 ppm」の画面と一致、96〜127 列なし。
- 感度確認: 送る値を 1235 ppm に変えると失敗（ページ 0 が不一致）。テスト本体は元に戻した。
- 判定が緩んでいないこと: 期待バッファは書籍スケッチ自体から生成し、結果に合わせた調整はしていない。ただし最終ページは比較対象外（モデルの確定遅れのため。理由は上記）。
