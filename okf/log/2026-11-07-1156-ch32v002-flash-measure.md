2026-11-07 11:56〜11:57 日本時間。ユーザーが WCH-LinkE を更新後、固定 ch32fun `2679ac059f3ada402731e5a10818cc0814e9ec4c` の minichlink は LinkE 2.22 と報告し、以前の 2.9 の未検出から通信可能になった。ユーザー申告では CH32V002 の開発ボードは先の CH32V003 ボードとピン互換。VDD–VSS 3.3 V、SWIO–VSS 0 V はユーザー実測。

固定 minichlink は `Detected: CH32V006` と `Flash Storage: 65535 kB` を表示した。ソース `pgm-wch-linke.c` は LinkE の応答 `0x4e` を CH32V006 に割り当てる。これはツールの表示上の処理であり、型番を証明しない。`minichlink -r + 0x1ffff704 4 -b` は `20 06 20 00` を返し、リトルエンディアンの識別値 `0x00200620` の上位型番部分は `0x002` だった。容量はデータシート上の16 KBを採用し、ツールの 65535 KB は採用しない。

1. `./scripts/ch32fun.sh build ch32v002` は成功。Flash 1060 bytes / 16 KB、静的 RAM 0 / 4 KB（スタックは別）。成果物 SHA-256 `770df168ba6081090c37d40b97e88761130951026d4112a2745dcb527a8ae647`。
2. `./scripts/ch32fun.sh flash ch32v002` は上記識別領域を事前照合後に書き込み、`Image written`、終了コード 0。
3. 固定 minichlink `-r <一時ファイル> flash 1060 -b` で読み戻し、`cmp` で成果物と一致。読み戻し SHA-256 も同じ。
4. 固定 minichlink `-b -T` は `blink_and_read CH32V002 started` と `PC0 high` / `PC0 low` の繰り返しを出力。5秒 timeout で取得終了（終了コード124）。
5. `python3 hardware/pico-tester/measure.py` は PASS。完全区間 50, 50, 51, 50, 50 サンプル。約10 ms間隔のため精密な周期測定ではない。

書き込み、照合、起動ログ、GPIO を別々に確認した。WCH-LinkE の更新が通信可能化の直前の変更だが、他の条件の影響を排除した比較試験ではない。スクリプトの002識別は、この固定版 minichlink と LinkE 2.22 の出力形式に依存する。別バージョンへの一般化は未確認。
