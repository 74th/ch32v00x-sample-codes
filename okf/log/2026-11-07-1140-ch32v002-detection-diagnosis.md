2026-11-07 11:40 日本時間。ユーザーは CH32V002 開発ボードに必要な線がつながっていると申告。WCH-LinkE は USB で認識され firmware 2.9 と報告される。固定 ch32fun `2679ac059f3ada402731e5a10818cc0814e9ec4c` の minichlink はソース上 CH32V002 検出コードを持つ。

同バイナリの `-t`、`-3`、`-i` を順に実行しても `No detected chip`、`Unknown chip fallback`、`Chip Type: 000` となった。返答は `81-55-01-01`、識別値は 0。`-i` の終了コード 0 は認識成功を意味しない。消去・書き込み・オプション変更は行っていない。実行後は 3.3 V 出力をオンに指示した状態。

原因は未確定。VDD–VSS と SWIO–VSS の電圧確認をユーザーに依頼。給電、基板配線、チップ上の既存設定、デバッグ接続、ツール・書き込み器の互換性などはこの結果だけでは切り分けできない。作業の続きは[差分・ビルド記録](2026-11-07-1130-ch32v002-port-build.md)を参照。

11:41、ユーザー測定では VDD–VSS は 3.3 V、SWIO–VSS は 0 V。測定時に SWIO をどちらが駆動していたかは未確認で、静止電圧だけから信号不良とは断定できない。同時刻に再度 `-i` を実行したが未検出は変わらなかった。[CH32V002 データシート V1.7](../sources/ch32v002-datasheet.md) §1.4.17（PDF p.12）は電源投入・リセット直後の SWIO と、実行中のデバッグ無効化および HSI の必要性を説明している。既存ファームウェアの設定は不明。消去や復旧操作は行っていない。

ユーザーは WCH-LinkE の SWIO からチップ PD1 までの導通、および PD1–VSS の短絡がないことを確認したと報告。個体故障も候補だが、この測定だけでは確定できない。基準として同じ書き込み器・配線で CH32V003 を再検出できるか、さらに別の CH32V002 個体で比較する方法がある。チップ交換は人の作業が必要で、まだ実施していない。
