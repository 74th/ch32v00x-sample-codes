# CH32V006 での WWDG の HIL（change `add-wwdg-sample` タスク 6.3、6.4）

CH32V002 の観測（[別ログ](2026-11-09-0013-add-wwdg-sample.md)）とは別に、CH32V006 実機で観測した記録。002 の結果は引き継いでいない。

## 条件
- 実行日: 2026-11-09 JST。`date` の読み取りは 07:51:37（接続確認）、07:53:04（1 回目の HIL の終了）、07:53:28（再実行の開始）、07:54:50（再実行の終了）。
- DUT: ユーザーの申告「006に差し替えた」。minichlink の検出出力は `Detected CH32V006`、`Flash Storage: 62 kB`（WCH-LinkE 2.22）。識別領域 0x1ffff704 の単独読み取りは、この確認では失敗（`couldn't detect memory region`）。書き込みは `Dut.flash` が識別領域を照合して行う（試験が通っている）。
- ソース: 002 と同一（WCH SDK は `samples_ch32v006_wch/wwdg`、ch32fun は `samples_ch32v00x_ch32fun/wwdg` を `TARGET_MCU=CH32V006`）。ソースはコミット前（`77c6ccc+dirty`）。
- Pico（GP9 = DUT の PD5 を UART 受信、1 回 32 バイト）、試験の流れ・判定は 002 と同じ（`tests/hil/wwdg_flow.py`、`ch32hil/wwdg.py`）。

## 実行（実測）
1. `uv run pytest --hil --hil-device ch32v006 --hil-framework wch tests/hil/wch/test_wwdg.py -q` → 3 passed（41.8 s）。
2. `uv run pytest --hil --hil-device ch32v006 tests/hil/test_wwdg.py -q` → 3 passed（39.2 s）。
3. 観測値を残すため、同じ 2 つを `--hil-run-dir` つきで再実行 → それぞれ 3 passed（41.8 s、39.2 s）。以下は 3 の観測。

| モード | 観測（WCH SDK、ch32fun とも同一。3 回の取得とも同一） | 判定 |
| --- | --- | --- |
| 0 窓の内側でフィード | `cause=other\n` + 点 20 個。3 秒後の 3 回の取得は点 32 個のみ | リセットされない |
| 1 早すぎるフィード | `cause=other\n.cause=WWDG\n.cause=W` | 点 1 個でリセット、要因は WWDG |
| 2 フィードしない | `cause=other\n.........cause=WWDG\n`（点 9 個） | 約 43.7 ms でリセット、要因は WWDG |

- 各試験の最後に既知のサンプル（WCH は `blink`、ch32fun は `blink_and_read`）を書き込み直す復旧も、全 12 回の試験で成功（試験が通った）。
- `artifact_sha256`（先頭 12 桁）: WCH: モード 0 `fe5f71f338ef`、1 `e7ba1ddf52b8`、2 `164ca5b4b9a4`。ch32fun: モード 0 `80b35b5ee80d`、1 `6397a6297d74`、2 `c279c14bb3dd`。
- 002 の観測と文字列まで同一だった（実測の比較。同一であることは 002 の結果の流用ではなく、006 で観測した結果）。
