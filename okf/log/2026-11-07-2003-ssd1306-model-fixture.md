# SSD1306 模擬の治具実装（verify-ch32fun-extralibs-with-pico タスク 3.1〜3.3）

- 実行日時（実測）: 2026-11-07 19:55〜20:03 JST。Pico への書き込みは 19:59 JST（シェルの `date`）。記録は 20:03 頃。
- 目的: DUT の SSD1306 helper を検証するため、Pico を I2C 0x3C の SSD1306 として振る舞わせる治具能力を追加する。
- 条件: ベース `fb156e5`（作業ツリーは未コミット）、Pico SDK `~/.pico-sdk/sdk/2.2.0`（commit `a1438dff…`、README の固定値と一致を確認）。配線は DUT 固定配線のまま（Pico 単体の I2C loopback 配線ではない）。

## 実装した内容

- `hardware/pico-tester/ssd1306_model.c/.h`: ハード非依存の解釈ロジック（制御バイトの Co/DC 分類、転送をまたぐ引数、水平/垂直/ページの各アドレッシング、ウィンドウ、表示 on/off、チャージポンプ、未対応コマンドの記録、CRC-32）。
- `ssd1306_fixture.c`（コマンド解析・応答整形）と `ssd1306_hw.c`（I2C1 slave 0x3C、GP10/GP11）。コマンド `SSD1306_CAPTURE <frames> <timeout_ms>`、`SSD1306_PAGE <0-7>`、`SSD1306_SELFTEST`。
- 設計との差分（要反映）: design は `SSD1306_CAPTURE <timeout_ms>` としていたが、`ssd1306_init` が最後に空フレームを送る（`ssd1306.h` の `ssd1306_init` が `ssd1306_refresh` を呼ぶ）ため、待つフレーム数を引数 `frames` に加えた。

## 実行と結果

1. `uv run pytest -q tests/unit`: 141 passed（実測）。うち新規は SSD1306 モデル 10 件、プロトコル（引数範囲、取得前の PAGE エラー、CAPS、取得結果と CRC、タイムアウト）、256 桁応答行の解析。これらは Pico のハードウェア呼び出しをスタブにしたホスト試験で、実機の I2C 経路は含まない。
2. `cmake --build`（Pico firmware）: 警告・エラーなしでビルド成功（実測）。
3. `picotool load -f -v -x …/pico_gpio_tester.uf2`: 書き込みと検証 OK、再起動して USB 応答（実測）。
4. DUT 配線のまま `CAPS` → `SSD1306_CAPTURE`/`SSD1306_PAGE`/`SSD1306_SELFTEST` が列挙された。`SSD1306_PAGE 0`（取得前）→ `ERR INVALID no_capture`。`SSD1306_CAPTURE 1 100`（DUT は i2c_slave_helper で 0x3C へ送らない）→ `ERR TIMEOUT frames=0 … safe=1`。`RESET_SAFE` OK（実測）。

## 失敗・訂正

- 初回の `cmake --build` は `PICO_SDK_PATH` 未設定で再構成に失敗した（環境変数の指定漏れ。実装の問題ではない）。
- テスト用スタブの初期化コマンド列の分割を誤り、2 件が失敗した（スタブの誤り。修正して通過）。

## 3.3 実 I2C 経由の自己検証（追記、20:01〜20:02 JST の実測）

- 配線: ユーザー申告で Pico 単体の I2C loopback（GP16–GP18 SDA、GP17–GP19 SCL、4.7 kΩ pull-up）へ切り替え済み。私は配線そのものは確認していない。既存 `I2C_SELFTEST MASTER0` が通ることで、バスとして成立していることだけ確認した（実測）。
- 1 回目（`uv run python hardware/pico-tester/ssd1306_selftest.py`）: 3 秒の応答待ちで空応答。切り分けで `SSD1306_SELFTEST` を直接実行すると 8.5 秒かかり `ERR I2C selftest frames=0 … wrong_address_rc=-2`（master の全書き込みがタイムアウト）。
- 原因（私の実装ミス）: `slave_begin()` 内の `fixture_safe()` が、先に設定した I2C0 の GP16/GP17 の機能設定を消していた。slave を先に設定し、その後で master のピンを設定する順序に修正。あわせて NACK 判定を `-1` のみに厳密化（-2 のタイムアウトを NACK とみなさない）。
- 修正後（再ビルド、`picotool load` で再書き込み、`ssd1306_selftest.py`）: 2 回とも `OK frames=2 unknown=1 bad_control=0 overflow=0 crc32=177d737d expected_crc32=177d737d wrong_address_rc=-1 idle_frames=0 safe=1`。`SSD1306_SELFTEST x` は `ERR INVALID arguments`、GP16〜19 は出力 0・pull なし。`PASS`。
- 範囲: 期待 CRC は、模擬の解釈ロジックを通さず、送ったパターンのバイト列から直接計算した値（CRC 関数のみ共有）。不完全な転送、`bad_control`、`overflow` の発生は実機では試しておらず、ホストのモデル試験でのみ確認。
