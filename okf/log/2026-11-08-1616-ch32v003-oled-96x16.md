# CH32V003 Arduino i2c_oled: 96x16 宣言でバッファを縮小する試行

- 作業日時: 2026-11-08 16:14:48〜16:16:53 JST（`date` で確認）。記録は 16:20 JST 頃。この change（add-ch32v006-arduino-wch）の範囲外の追加作業（ユーザー依頼）。
- 対象: CH32V003（ユーザー申告で差し替え済み。minichlink の `Detected CH32V003` は flash ガードが確認）。配線は固定治具、電圧は未測定。実 OLED は使わず Pico の SSD1306 模擬のみ。
- ツール: arduino-cli 1.5.1 / core 1.0.6 / OLED SSD1306 - SH1106 1.0.7（固定）/ GCC 15.2.0。ソースは HEAD 532bf54＋未コミット変更。

## 変更（書籍からの逸脱）
- `samples_ch32v003_arduino/i2c_oled_96x16/` を追加。書籍の `i2c_oled.ino` との差は `OLED::W_128, OLED::H_32` → `OLED::W_96, OLED::H_16`（バッファ 512 B → 192 B）のみ。描画呼び出しは書籍のまま（範囲外はライブラリが切り捨て、`draw_pixel` で境界確認。`draw_byte` の境界確認までは読んでいない）。
- ライブラリが対応するサイズは 96x16 / 128x32 / 128x64 のみで、描画範囲だけの縮小機能はない（ヘッダ・ソース確認）。

## 結果
- build（実測）: Flash 10,912 B / 16,384 B、RAM 1,096 B。ELF のヒープ `_end=0x20000448`〜`_heap_end=0x20000640`（504 B）は元と同じで、192 B は収まる。
- 失敗と修正（実測）: 初回は `SSD1306_CAPTURE` の timeout に 6000 ms を指定して `ERR INVALID ssd1306_capture_arguments`（上限 5000 ms、私の設定ミス）。次に診断で frames を変えて調べ、frames=1 が 3.18 s で完了（transfers=18、data=768 B＝192 B×4 回の display()）、frames=2 以上は timeout と分かった。
- 期待値の修正（実測に基づく）: `OLED::begin()` は空白のバッファを 1 回 `display()` する（ソース確認）。このためモデルのページ 0〜1 は空白、2〜7 が描画内容（ホストの harness で生成した 96x16 バッファ）になる。最初の期待値（全ページ描画内容）は誤りで、実測の不一致から修正した。判定は「ページ 0〜1 が空白、2〜7 が期待バッファと一致、96〜127 列は 0、display on・charge pump on、bad_control/overflow なし」。
- HIL `test_arduino_i2c_oled_small_buffer`: 修正後 2 回連続で passed（8.55 s 前後）。frames=1、crc32=5adc31ab、unknown=0。
- 対照: 元の `test_arduino_i2c_oled`（128x32）は 003 で従来どおり xfail（malloc(512) 失敗）。

## 意味と未確認
- 003 で OLED ライブラリを使い、描画内容がバッファ経由で Pico の模擬に正しく届くことを確認した（機能のみ）。表示領域は 96x16 に縮むため、書籍と同じ表示ではない。
- 実 OLED の表示、96x16 パネルでの見え方、`printf` 一時バッファ等を使う別描画での heap 余裕は未確認。
- 003 の他の Arduino サンプルへの影響は未確認（今回は i2c_oled のみ）。
