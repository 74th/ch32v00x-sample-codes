## 事前変更
- `tests/hil/wch/test_adc.py`・`test_adc_dma.py` の SCALE に `ch32v006: (4095, 2800, 1200, 80)` を追加。根拠: 006 は 002 と同じ 12-bit ADC・同じ SDK で、比率は 002 と同じ（結果に合わせた調整ではない）。実測で 4018 / 4014 を読んだので 12-bit 全域で動作している。

## 結果（実測）
- `uv run pytest --hil --hil-device ch32v006 --hil-framework wch -m 'hil and wch' tests/hil/wch/{test_uart,test_i2c_master,test_i2c_slave,test_spi_master,test_adc}.py`: **5 passed**（40 s）。ADC は x_high_y_low=(4018, 0)、x_low_y_high=(0, 4014)、both_low=(0, 0)、ステップ x=[2454, 3323, 3710] y=[2455, 3326, 3713]。uart は Pico がセンサー役で、既知フレーム→「CO2:  1234 ppm」、チェックサム不正、無応答→timeout の文字を確認。i2c_master（SHT31 模擬）、i2c_slave（Pico master）、spi_master（Pico slave）は通信内容が一致。
- **pwm（PC4 問題）**: 002 と同じ PD2＋PC4 のままだと 006 では PC4 が無信号（[Arduino 側のログ](2026-11-08-1550-ch32v006-arduino-hil-batch1-pwm-pc4.md)参照、WCH SDK でも同じ症状）。ユーザー判断（「PD2、PC0 で動作したならば一旦よい」）で、006 の `pwm` の既定を **TIM2_CH3 on PC0**（`USE_PC0=1`、周期・プリスケーラ・コンペア値は同一）に変更した（書籍の SDK サンプルからの逸脱）。PC4 版は `EXTRA_CFLAGS=-DUSE_PC0=0` でビルドでき、参考試験 `test_wch_pwm_pc4_reference`（xfail 非 strict、結果は別ファイル）として維持。
- 変更後 `test_wch_pwm`: 3 回連続 passed（各 約 11 s）。PC4 の参考試験は XFAIL（無信号のまま）。
- 失敗と修正（テストの不備、実測）: 追加直後の 2 回目に `PC4 (CH4) shows no ramp` で失敗。原因は、参考試験の後に既定へ戻す再ビルドで、`make` が `EXTRA_CFLAGS` の変更を検知せず PC4 版の成果物をそのまま書き込んだこと。非空の `make_args` で強制クリーンビルドにしてから 3 回連続で合格。ファームウェアの不具合ではない。

## 判断
- adc / uart / i2c_master / i2c_slave / spi_master は 003・002 と同じ判定基準で合格。pwm は PD2＋PC0 の組で合格（書籍相当の PD2＋PC4 は未確認、原因未特定）。
- 機能確認のみ。ADC の精度・校正、時間精度、実センサー、PC4 の原因は未確認。
