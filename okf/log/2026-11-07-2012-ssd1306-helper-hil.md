# SSD1306 helper サンプルの HIL（verify-ch32fun-extralibs-with-pico タスク 4.1〜4.4）

- 実行日時（実測）: 2026-11-07 20:05〜20:11 JST（シェルの `date`）。記録は 20:12 頃。
- 目的: 固定 submodule の `extralibs/ssd1306_i2c.h` + `ssd1306.h` を使う DUT サンプルが送る SSD1306 の通信を、Pico の SSD1306 模擬で受けて、ホストで生成した期待フレームと照合する。
- 条件: CH32V003F4P6、固定配線 PC1/PC2–GP10/GP11（DUT 側 pull-up）。Pico は GP16〜19 に I2C loopback 配線が接続されたままだが DUT 試験には使わない（ユーザー申告の配線）。submodule `b28d285`、ベース `fb156e5`（作業ツリーは未コミット）。
- サンプル: `samples_ch32v003_ch32fun/ssd1306_i2c/`（`scene.h` を DUT とホストで共有）。既定ビルドは `ssd1306_i2c_init()` 後に I2C1 の CKCFGR を 100 kHz 標準モードへ書き換える。`make HELPER_CLOCK=1` は helper 既定の 1 MHz のまま。helper は `SSD1306_I2C_CLKRATE` を `#ifndef` なしで定義するため define では上書きできない。
- 期待値: ホストの gcc で、同じ固定 submodule の `ssd1306.h`・同じ `scene.h` を実行し、`ssd1306_pkt_send` を模擬の解釈ロジックへ渡して生成（`ch32hil/expected.py`）。期待 CRC は `3bd75961`。空フレーム CRC は `efb5af2e`。

## 結果（実測）

- build: 100 kHz 版 FLASH 5416 B、1 MHz 版 5364 B、RAM 1 KB。map に book-code への参照なし。
- 100 kHz: 最終構成で 3 回連続 passed（約 3.5 秒/回）、全体実行でも passed。判定内容: フレーム CRC が期待値と一致、`unknown=0`、`bad_control=0`、`overflow=0`、`display_on=1`、`display_on_seen=1`、`charge_pump=1`。
- helper 既定 1 MHz: 2 回とも `transfers=0`（4 秒の待機内に Pico が 1 転送も受信せず、`ERR TIMEOUT`）。原因は未切り分け（Pico slave が 100 kHz 設定のため、波形が間に合わない、DUT が送っていない、のいずれもありうる）。参考情報として `xfail`（非 strict）で記録する。

## 経緯と失敗（時系列）

1. 1 回目: テストコードのバグ（シリアルポートを閉じた後に Pico クライアントを使用、`PortNotOpenError`）。DUT の build/flash/readback は pass。ページ取得をポートを開いている間に行うよう修正。
2. 2〜5 回目: CRC 不一致（取得 `efb5af2e` = 全ゼロ、期待 `3bd75961`）、`transfers=163`、`cmds=68`、`data≒3037`。DUT を書き換えず Pico 取得とリセットだけで切り分け（scratchpad の使い捨てスクリプト）:
   - DUT を先にリセットして取得 → frames=1 は空フレーム、frames=2 と 3 は CRC `3bd75961` = 期待値と一致（transfers 63/101/139）。
   - 取得直前に `minichlink -i`（検出確認）を実行すると、`-i` が DUT を再起動し、続く `-b` で 2 回目の起動となり初期化が 2 回流れる（cmds 68 = 初期化 2 回）。最終フレームが空フレームになる。
   - 当初の `INIT`（最初の 0xAE から同期）では 2 回起動を除けなかったため、`INIT` を「表示オフを受けるたびに模擬をクリアし、最後の初期化から数える」に変更（Pico firmware 更新・再書き込み）。テストからは取得待機後の `minichlink -i` 呼び出しも外した。
3. 上記修正後に 100 kHz が安定して通過。

## 判定範囲と未確認

- 確認したこと: 100 kHz の I2C で、helper の初期化コマンド列と 2 フレーム分の表示データが、ホストで同じコードから生成した期待フレームバッファと一致して Pico に届いた。
- 実 OLED での表示、1 MHz の通信（上記）、複数回リセットを跨ぐ再現性（今回は各回で build・flash・reset を実施した 3 回＋全体 1 回のみ）、電気的波形は未確認。
- 期待フレームは helper 自身の描画コードから生成しているため自己参照を含む。別に、枠線・スプライト・ドットなどの画素位置をホストの単体テスト（`tests/unit/test_ssd1306_expected.py`）で独立に確認している。
