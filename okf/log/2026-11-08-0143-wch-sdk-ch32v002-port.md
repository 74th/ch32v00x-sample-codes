# WCH公式SDK CH32V002への移植（タスク3.1〜3.15、build-onlyで実機未観測）

作業日時: 2026-11-08 01:43 JST（ホストdateで確認、記録は作業直後）。**CH32V002の実機は接続していない**（接続中はCH32V003）。書き込みは行っていない。

## 目的・条件
changeのセクション3。CH32V002専用の公式SDK（externals/ch32v002_004_005_006_007 revision a835ede9ff3e2dca2c6aa652809b85c9775475d2）を`samples_ch32v002_wch/sdk`へコピーし、003の13サンプル＋blinkを移植してビルドする。WCH GCC 15.2.0。

## 実行（ホストのみ）
```sh
make -C samples_ch32v002_wch/<sample> clean build        # 14個
riscv32-wch-elf-gcc -E -dM -DCH32V002 ... <<< '#include <ch32v00x.h>'      # 型番マクロの確認
uv run pytest tests/unit -q
```

## 結果（実測はビルドとホスト単体テストのみ）
- 14個すべて16K/4Kでビルド成功（Flash/RAMは各README）。blink: Flash 1,796 B／RAM 524 B。mapで`FLASH 0x4000`、`RAM 0x1000`、スタック上端0x20001000、ISAタグ`rv32e2p0_c2p0_zmmul1p0_zca1p0`。
- `-DCH32V002`で`CH32V002`が定義され`CH32V006`は定義されない（未指定だと`CH32V006`）。
- 003 SDKとの差を修正して移植: RCC名（APB2→PB2など）、GPIO速度（30 MHzのみ）、ADC（12-bit、校正API無し→省略、サンプル時間CyclesMode7、ADCクロック設定）。blink以外の初回ビルドの失敗はこれらの名前差とADCのみ。
- ホスト単体テスト（002の設定・ファイルに003が混入しないこと、型番識別領域ガード、matrix網羅）を追加し全て成功。
