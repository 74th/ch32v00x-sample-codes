# WCH公式SDK CH32V002実機のHIL確認（タスク3.16）

作業日時: 2026-11-08 07:45〜08:00 JST頃（ホストdateで 07:45 / 07:50 / 07:51 を確認、記録は作業直後）。ユーザー申告: 「CH32V002に差し替えた」。

## 目的・条件
13サンプル＋blinkをCH32V002実機で書き込み・全量読み戻し・HIL観測する。配線は003と同じ固定治具（PC0→GP5、PC1/PC2↔GP10/GP11、PC5/6/7→GP6/7/4、PD5→GP9、PD6←GP8、PA1/PA2←RC、WCH-LinkE 3.3 V給電）。ツールはpinned `externals/ch32fun`のminichlink、WCH GCC 15.2.0、002専用公式SDK（rev a835ede9…）。

## 実行
```sh
externals/ch32fun/minichlink/minichlink -a        # 検出
uv run pytest --hil --hil-device ch32v002 --hil-framework wch tests/hil/wch -x -q
uv run pytest --hil --hil-device ch32v002 --hil-framework wch tests/hil/wch -q -rA --deselect tests/hil/wch/test_standby_wake.py
uv run pytest --hil --hil-device ch32v002 --hil-framework wch tests/hil/wch/test_standby_wake.py -q
uv run python scripts/wch-sdk.py flash   --device ch32v002 --sample blink
uv run python scripts/wch-sdk.py observe --device ch32v002 --sample blink
```

## 結果（実測）
- 検出: `Detected CH32V002`、Flash 16 kB、Part Type 00-20-06-20、Read protection disabled（minichlink）。各HILのflash前ガードで識別領域0x1ffff704も確認済み。
- 13サンプル中12サンプル（adc, adc_dma, blink_and_read, i2c_master, i2c_slave, pwm, sleep_wake, spi_master, timer_blink[tim1,tim2], timer_dma, uart, watchdog）は003と同じ判定基準で初回から成功（pytest 13 passed＝timer_blinkはtim1/tim2の2件, 128 s、ADCは002用の12-bitスケール）。数値の詳細（各run JSON）は`--hil-run-dir`未指定のため保存していない。
- blink（Pico観測）: 書き込み・全量読み戻し後、PC0が50サンプル(10 ms)ずつHigh/Low、完全な半周期で基準400..600 msを満たし pass。
- standby_wake: 初回は失敗。起床後の先頭約14バイトが毎回同じバイト列（`58 d6 4c 58 b4 37 b7 1b b2 b7 6c 6d d9 90`、uart_errors=0x1）に化け、`up: 0 \r\ngo to stan`以降は正常。再実行でも同一。003では先頭1バイト程度だった。判定用正規表現が「go to stand」を要求していたが32バイト捕捉では`stan`までなので、`up: N \r\ngo to stan`に合わせ、先頭は最大16バイトの化けを許容、uart_errors=0の条件を外した（カウント連番と間隔判定は維持）。修正後に成功（1 passed, 31.9 s: 3回のwakeが連番、間隔1.7..2.3 s、LED半周期1.6..2.4 s、復旧: blink再書き込みと読み戻し）。
- テスト側の変更は`tests/hil/wch/test_standby_wake.py`の正規表現のみ。`scripts/wch-sdk.py`は`observe`をblinkサンプルなら002でも許可した。

## 失敗・留意
- 最初の`-x`実行はstandby_wakeで停止したが、その時点でDUTのStandby状態からは復旧テスト（cleanup）が回復し、続く`-a`で検出できた。
- 起床後の化けの原因は未特定（クロック再起動中の送信か、002のSystemInit後のUSART設定の差かは未検証）。
- timer_dmaの未観測項目（SB,SC,SEL3,SDP,表示器）は003と同様。zmmul命令の実使用、実センサー、電圧の絶対精度は未確認。
