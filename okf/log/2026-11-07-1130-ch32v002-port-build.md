2026-11-07 11:30〜11:32 日本時間。ユーザーは開発ボードをピン互換の CH32V002 に差し替えたと申告。固定版 minichlink の `-i` は `No detected chip` と未知チップを報告し、終了コードは 0 だった。実機はまだ識別できず、書き込み・動作は未確認。

# 差分調査

- ターゲット: 固定 ch32fun `2679ac059f3ada402731e5a10818cc0814e9ec4c` の `ch32fun.mk` は `CH32V002` で `CH32V00x`、リンク設定 5、GCC 13 以降に `rv32ec_zmmul/ilp32e` を選択。CH32V003 は別の `CH32V003` と `rv32ec/ilp32e`。この対応の実機妥当性は未確認。
- メモリ: [CH32V002 データシート V1.7](../sources/ch32v002-datasheet.md) PDF p.2, p.8 と [CH32V003 データシート V1.8](../sources/ch32v003-datasheet.md) PDF p.2 では両者とも Flash 16 KB、RAM は 002 が 4 KB、003 が 2 KB。WCH SDK `a835ede9ff3e2dca2c6aa652809b85c9775475d2` の `EVT/EXAM/SRC/Ld/Link.ld` にも002用 16K/4K の記述があるが、その共有ファイルの有効な既定設定は別デバイス用であり、002 の記述はコメント内にある。ch32fun は002用に 16K/4K を選ぶ。
- GPIO: 002 の資料 PDF p.13, 16–17 と 003 の資料 PDF p.13–14 では、F4P6 の PC0=10、PA1=5、VSS=7、VDD=9、PD1/SWIO=18。GPIO の MODE ビット差は [GPIO CFGLR の差分](../peripherals/gpio/cfglr-mode-field.md) を参照。PC0 出力の MODE は予約ビットを立てず 1 を使用。PA1 はプルアップ入力、プルダウンの問題は対象外。
- クロック: 002 資料 V1.7 §1.4.10 と WCH SDK `GPIO/GPIO_Toggle/User/system_ch32v00X.c` は HSI と 48 MHz 設定を扱う。固定 ch32fun の CH32V00x 分岐では HSI 値の既定定義がないため、サンプル側で `HSI_VALUE=24000000` を指定し、既定の PLL 倍率 2 を使う。周波数は資料・コード上の設定であり実測ではない。
- 起動: WCH SDK `EVT/EXAM/SRC/Startup/startup_ch32v00X.S` は gp・sp、データ・BSS、割り込み・ベクタを初期化し `SystemInit` を呼んで `main` へ移行する。固定 ch32fun の `ch32fun.c` は独自スタートアップで gp・sp、BSS・データ、割り込み・ベクタと SysTick を初期化し `main` へ移行する。ch32fun 版は startup で `SystemInit` を呼ばず、サンプルの `main` から呼ぶ。WCH SDK のハードウェアスタック設定は常時有効、ch32fun は `FUNCONF_ENABLE_HPE` に依存する。GPIO の起動・点滅は[実機で確認](2026-11-07-1156-ch32v002-flash-measure.md)したが、割り込みやハードウェアスタックの動作は未検証。

# build-only

`make -C samples/ch32v002/blink_and_read build PREFIX=riscv64-unknown-elf` は成功。RISC-V GCC 14.2.0、Flash 1060 / 16384 bytes、静的 RAM 0 / 4096 bytes（スタックは別）。`main.bin` SHA-256 `770df168ba6081090c37d40b97e88761130951026d4112a2745dcb527a8ae647`。`objdump -h` で実行コードが 0x00000000〜0x00000423、RAM セクションが 0x20000000 にあることを確認。ビルド成功は実機の動作保証ではない。

初回ビルドでは upstream の makefile が生成リンカスクリプトの指定を上書きし、`externals/` 内に生成した。project Makefile の `override` で `generated_ch32v002.ld` をサンプル側に生成するよう修正し、再ビルドした。upstream の追跡ソースは編集していない。
