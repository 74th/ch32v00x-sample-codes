# CH32V006F8P6 の検出と識別領域の読取（読取のみ、書き込みなし）

- 作業日時: 2026-11-08 13:24 JST 頃（`date` は 13:24:23 JST）。記録は 13:26 JST。
- 目的: タスク 4.1 の一部。差し替え済み DUT が CH32V006 として検出され、識別値の上位型番が `0x006` であることの確認。
- 条件（ユーザー申告）: 「今 CH32V006F8P6 が刺さっている」。F8P6 と F8P7 は同一ダイで温度グレード違い（STM32 の例からの推測。現行は高温品の F8P7 のみ出荷されるのでは、という仮説）。**この同一視は申告に基づく作業上の仮定で、資料確認ではない**（[型番メモ](../devices/ch32v006-tssop20-part-number.md)）。
- 未確認（今回聞いていない）: 刻印の全文、向き、配線の実態（Pico 接続の有無）、VDD–VSS・SWIO–VSS の電圧値。WCH-LinkE は DUT へ 3.3 V を出力した可能性がある（給電値は未測定）。
- ツール: 固定 `externals/ch32fun` の minichlink（`./scripts/ch32fun.sh programmer` でビルド）。WCH-LinkE ファームウェア 2.22（出力より）。

## 実行コマンド
```sh
externals/ch32fun/minichlink/minichlink -i
externals/ch32fun/minichlink/minichlink -r + 0x1ffff704 4 -b
```
どちらも読取のみ。flash 書き込み・消去は行っていない（`-b` は読取後のリセット/ブート指定。DUT の実行状態はリセットされ得る）。

## 結果（実測）
- `Found WCH Link`、`Detected CH32V006`、`Flash Storage: 62 kB`、`Read protection: disabled`。
- `Part Type: 00-63-06-20`。
- `1ffff704: 20 06 63 00` → リトルエンディアンで `0x00630620`、上位 12 bit = `0x006`（期待どおり。下位は revision 等の証跡として記録）。
- UID は出力されたがこのログには転記しない。
- 資料（ESIG の Flash 容量等）との照合: 62 kB は F8P7 の記載（62K）と一致。ピン機能・温度グレードは未確認。

## 判断
- CH32V006 であり、Flash 容量が 62 kB という点で F8P7 の記載と矛盾しない（実測）。F8P6 と F8P7 の関係は引き続き仮定のまま。
- flash・HIL は未実施。
