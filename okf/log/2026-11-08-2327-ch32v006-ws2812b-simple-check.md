# ch32fun `extralibs/ws2812b_simple.h` が CH32V006 で動くか（簡易確認）

- 記録: 2026-11-08 23:27〜23:30 JST（`date` で取得）。ユーザーの問い「サクッと動くかどうか確認できそう？ CH32V003 専用の雰囲気？」に答えるための確認。change には属さない（`fix-ch32v00x-sample-findings` の 7.9 の判断材料）。
- 対象: CH32V006F8P6（22:37 にユーザーが差し替えたまま。flash ガードで識別 0x006）、固定配線（PC6 → GP7、1 kΩ）、WCH-LinkE の 3.3 V 給電。CH32V002 では試していない。
- helper: 固定 `externals/ch32fun`（`b28d285`）の `extralibs/ws2812b_simple.h`（83 行、submodule は変更しない）。

## ソースから分かったこと

- 冒頭のコメントは「for using asynchronous LEDs with the CH32V003 using GPIO」。
- 送信のたびに、ピンを `GPIO_Speed_2MHz | GPIO_CNF_OUT_PP`（MODE=2）に設定する（34 行目）。CH32V00x では MODE=2 は出力にならないことを 002/006 で実測済み（[ログ](2026-11-08-2137-fix-ch32v00x-sample-findings.md) 7.3、[006](2026-11-08-2237-ch32v006-sample-findings.md)）。
- 時間は `DelaySysTick(25)`（「1」の High）、`DelaySysTick(1)`、`DelaySysTick(15)` と、「0」の High の `nop` 4 個で作る。`FUNCONF_SYSTICK_USE_HCLK 1` が必須（`#error`）。

## 実機での確認

- 診断ファーム（scratchpad、使い捨て）: 6 LED 分の固定の 18 バイトを、100 ms ごとに `WS2812BSimpleSend(GPIOC, 6, …)` で送る。funconfig は `HSI_VALUE 24000000`、`FUNCONF_SYSTICK_USE_HCLK 1`。
  - `orig`: 固定 helper をそのまま使う。
  - `mode1`: helper の複製の 34 行目だけを `GPIO_Speed_10MHz`（MODE=1）に変えたもの（`-I.` で複製を優先。2 つの `.bin` が異なることを確認）。
- 観測: Pico の `WS2812_CAPTURE 7 18 1500` を 3 回、続けて `GPIO_SAMPLE 7 300 1000`。

| ビルド | WS2812_CAPTURE（3 回） | GP7 の標本化 |
| --- | --- | --- |
| orig（そのまま） | 3 回とも `TIMEOUT bits=0`（信号なし） | 300 標本すべて Low |
| mode1（MODE=1 の複製） | 3 回とも 18 バイトを期待どおり復号（`rx=00ffa55a…8118c3`）。ただし `bad_pulses` 24〜27、`t0h_ns=192`（範囲 192〜224）、`t1h_ns=1136`（1136〜1152）、Low は 1168〜2496 ns | フレームが短く、1 ms の標本ではすべて Low（参考） |

- 解釈:
  - **固定 helper のままでは、CH32V006 で信号が出ない**（ピンが出力にならない）。ソースの MODE=2 の設定と、MODE=2 の実測と一致する。
  - MODE だけ直すと、Pico はバイト列を復号できたが、時間は WS2812B の規格（T0H 400 ns ±150、T1H 800 ns ±150）に合わない（T0H 約 190 ns は短く、T1H 約 1140 ns は長い）。Pico の測定は未校正（偏り約 −32 ns の記録あり）。実物の LED が光るかは未確認。
  - CH32V002 も MODE=2 は出力にならない（実測済み）ので、同じく信号が出ないと推定する（002 では未実施）。
- 後片付け: 診断ファームが書き込まれたまま（006 は次の作業の前に既知のサンプルを書き込むこと）。
