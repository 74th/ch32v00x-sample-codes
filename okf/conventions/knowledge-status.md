# 確度（`evidence`）

各conceptのフロントマターに、プロジェクト独自のキー `evidence` を置く。READMEで定めた3区分に対応している。

| 値 | README上の区分 | 意味 |
| --- | --- | --- |
| `hardware` | 確認済み | 対象の型番と条件を記録した実機試験で確認した |
| `document` | 資料確認済み | 一次資料で確認したが、実機では未確認 |
| `hypothesis` | 仮説・要確認 | 移植や試験のために置いた仮説。根拠を追加する必要がある |

1つのconceptに確度の異なる主張が混ざる場合は、本文の該当箇所に確度を明記し、`evidence` にはもっとも低い確度を書く。

# 対象デバイス（`devices`）

`devices` に、記述が当てはまる型番かシリーズを列挙する。あるデバイスで確認した内容を、別のデバイスやパッケージの保証として扱わない。

# 出典

- 一次資料は [sources/](/sources/) にconceptとして登録し、各conceptの `sources` から参照する。
- 主張ごとの出典は、`sources[].id` をラベルにした脚注で示す。脚注には資料の版と、**PDFの通しページ番号**（`PDF p.N`）を書く。フッタに印字されたページ番号と異なる場合は、印字番号も併記する。
- 原文の転載はしない。目的に必要な事実、差分、制約を、独自の構造と表現で要約する。

# 信頼度と状態（OKF標準フィールド）

- `generated.by` は、エージェントなら `<producer>/<version>`、人なら `human:<id>` の形式で書く。
- `verified` は、人またはプロセスが一次資料・実機と照合したときに追記する。エージェントが自分で書いた内容を自分で照合した場合は、`verified` に記録しない（本文の照合記録に書く）。
- 人のレビューを受けるまでは `status: draft` とする。

# 公開範囲

PDF原本と変換データは非公開の作業領域（Git管理対象外）に置き、このバンドルには含めない。
